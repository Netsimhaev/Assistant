# testing — סיכום בעברית פשוטה של בדיקה שרצה

## מטרה

אחרי כל הרצה או בדיקה: לומר בשורות ספורות מה נבדק, מה יצא, ומה עכשיו.
הקורא אינו קורא פלט של vitest ואינו קורא הודעות של המהדר.

## מתי נדלק — לבד, בלי שמבקשים

מיד עם סיום כל אחת מאלה:
`npm test` · `npm run typecheck` · `npm run build` · `npm run migrate` · `npm run migrate:test` ·
`npm run scheduler` · `npm run sdk:know-reader` · הבדיקה האוטומטית שרצה בסוף התור.

לא נדלק על קריאת קוד, חיפוש, או פקודה שלא בודקת דבר.

## התבנית — כשעבר

**מה נבדק:** שורה אחת.

**התוצאה: עבר בהצלחה.** ✅

**מה עובד עכשיו בפועל:** עד שתי שורות. לא "144 מבחנים ירוקים", אלא מה המערכת מסוגלת לעשות בזכותם.

**ההמלצה להמשך:** שורה אחת — הצעד הבא הכי הגיוני.

## התבנית — כשנפל

**מה נבדק:** שורה אחת.

**התוצאה: נכשל.** ❌

**הסיבה:** שורה אחת בעברית. לא הודעת השגיאה — מה היא אומרת.

**איך מתקנים:** עד שלושה פתרונות, הסביר ביותר ראשון, שורה לכל אחד.

המילה **נכשל** נכתבת במפורש. "לא הכול עבר" או "כמעט הצליח" אינם תוצאה.
בדיקה חלקית היא כישלון: שלוש עברו ואחת נפלה — נכשל.

## כישלונות מוכרים בפרויקט הזה

| מה מופיע | מה זה אומר | הפתרון |
|---|---|---|
| שגיאת חיבור / `ECONNREFUSED` | בסיס הנתונים כבוי. המבחנים כאן דורשים Postgres אמיתי, אין חיקוי | להפעיל את שירות Postgres ולהריץ שוב |
| `database ... does not exist` | בסיס הבדיקות מעולם לא נוצר | ליצור `assistant_test`, ואז `npm run migrate:test` |
| `relation ... does not exist` | הסכמה ישנה — מיגרציה לא רצה | `npm run migrate:test` |
| `TEST_DATABASE_URL` חסר | אין קובץ `.env` על המכונה | להעתיק מ-`.env.example` ולמלא סיסמה |
| `possibly undefined` / `Property ... does not exist` | הגדרות טייפסקריפט המחמירות תפסו גישה לא בטוחה | לתקן בקוד. זו אינה תקלת סביבה |
| `Cannot find module './x'` | חסרה סיומת `.js` בייבוא יחסי — נדרשת כאן תמיד | להוסיף `.js` |
| `audit_log_no_update` | מבחן ניסה לשנות שורת ביקורת; הטבלה חסומה לעדכון בכוונה | לכבות את ה-trigger בתוך המבחן ולהחזירו בסופו |
| `אין ANTHROPIC_API_KEY` | ההרצה החיה דורשת מפתח ועולה כסף | אינה תקלה. לדלג, או להגדיר מפתח |
| מבחן של כלי חדש עובר מיד, בלי שנכתב קוד | כלי כתיבה שלא נרשם בשתי הטבלאות מטופל כקריאה-בלבד ועובר את השער בשקט | לרשום אותו ב-`classify.ts` **וגם** ב-`capabilities.ts` |

## כללי כתיבה

1. אפס פלט גולמי. לא מדביקים stack trace ולא שורות של vitest.
2. מספר נכנס רק כשהוא אומר משהו: "144 מבחנים עברו" כן, "144/144 ב-3.2 שניות" לא.
3. "מה עובד עכשיו" מנוסח כיכולת של המערכת, לא כשם קובץ.
4. לא מתקנים בתוך הסיכום. מציעים פתרון, ומחכים לאישור.
5. אם הבדיקה לא רצה בפועל — אומרים זאת. "נראה תקין" בלי הרצה אינו דיווח.

## דוגמא — כשנפל

**מה נבדק:** כל מבחני המערכת.

**התוצאה: נכשל.** ❌

**הסיבה:** בסיס הנתונים של הבדיקות אינו קיים. המבחנים כאן עובדים מול Postgres אמיתי ולא מול חיקוי, ובלעדיו אף מבחן לא יכול לרוץ.

**איך מתקנים:**
- לוודא ששירות Postgres דלוק על המחשב.
- ליצור בסיס נתונים בשם `assistant_test`.
- להריץ `npm run migrate:test` כדי לבנות בו את הטבלאות.
