# projectpro — דוח מצב פרויקט ב-PDF

## מטרה

תמונת מצב לכל שלב בפרויקט: מה הושלם, מה בעבודה, מה טרם החל, וכמה נשאר כדי לסגור את השלב הנוכחי.
הדוח נועד לקריאה של מי שאינו קורא קוד — עברית פשוטה, בלי קטעי קוד, בלי שמות פונקציות.

## הסקיל הזה לא מבצע

קורא, לומד, מסכם ומייצר קובץ אחד. זהו.

- לא מתקן קוד, לא מריץ מיגרציות, לא משנה הגדרות — גם כשהדוח מצביע על תקלה.
- הפלט היחיד שנכתב הוא ה-HTML וה-PDF תחת `reports/`.
- משימה שהתגלתה תוך כדי נכנסת לפרק "משימות פתוחות", לא ליישום.

## שלושת הצבעים — הכלל שקובע

| צבע | מתי | הראיה הנדרשת |
|---|---|---|
| 🟢 **ירוק** | הושלם במלואו | הקוד קיים **וגם** יש מבחנים שעוברים **וגם**, אם נגע בליבת המדיניות, עבר סקירת אבטחה |
| 🟡 **צהוב** | בעבודה | הקוד קיים אבל חסר אחד מהשלושה: מבחנים, סקירת אבטחה, או קורא אמיתי (מודול שמתקמפל ואף אחד לא משתמש בו) |
| 🔴 **אדום** | טרם החל | אין קובץ, אין מבחן, ואין הפניה אליו בקוד |

**כלל הגלישה למעלה:** שלב־אב נצבע בירוק רק כשכל המשימות שבתוכו ירוקות. משימה צהובה אחת צובעת את כל השלב בצהוב.

**"קיים" אינו "הושלם".** כל שורה ירוקה חייבת לשאת בעמודת הראיה משפט שמוכיח זאת. בלי ראיה — צהוב.

## מאיפה לוקחים את האמת

| שאלה | המקור |
|---|---|
| מהם השלבים ומה יש בכל אחד | `docs/09-roadmap.md` — כל תבליט הוא שורה בדוח |
| מה כבר נבנה | `src/` והיסטוריית הקומיטים |
| מה באמת עובר בדיקות | `npm test` — מריצים, לא מניחים |
| מה ידוע כפתוח | `CLAUDE.md` — "בעיות ידועות" ו"מה עוד לא נבנה" |
| מה דורש סקירת אבטחה | קומיטים שנגעו ב-`policy/`, `charter/capabilities.ts`, `audit/`, או במיגרציות |

## איך מייצרים את הקובץ

1. להעתיק את [report-template.html](report-template.html) ולמלא אותו בתוכן.
2. לשמור כ-`reports/status-YYYY-MM-DD.html`.
3. להמיר, ולמסור למשתמש את הנתיב:

```bash
# הנתיבים חייבים להיות מוחלטים ובסגנון Windows — נתיב יחסי נשלח לחיפוש ברשת ונכשל ב-DNS.
ABS="$(pwd -W)/reports/status-YYYY-MM-DD"
"/c/Program Files/Google/Chrome/Application/chrome.exe" --headless --disable-gpu \
  --no-pdf-header-footer --print-to-pdf="$ABS.pdf" "$ABS.html"
```

הפקודה מדפיסה כמה בייטים נכתבו. אין פלט כזה — ההמרה נכשלה, ואין למסור קישור לקובץ שלא נוצר.
ל-Edge יש אותם דגלים בדיוק, אם Chrome אינו מותקן.

## כללי כתיבה בדוח

1. כל שורת משימה נקראת בלי רקע טכני: "העוזרת יודעת לקרוא מסמך", לא שם המודול.
2. עמודת הראיה היא משפט אחד — מה מוכיח שזה במצב הזה.
3. הצבע לעולם אינו המידע היחיד: כל תא נושא גם את המילה (הושלם / בעבודה / טרם החל), כי דוח מודפס בשחור־לבן חייב להישאר קריא.
4. פרק המשימות הפתוחות מדורג — הראשונה היא מה שחוסם הכי הרבה, לא מה שהכי קל.
5. אין בדוח קטעי קוד. שם קובץ מותר רק בעמודת הראיה, ורק כשאין דרך אחרת.

## טעויות נפוצות

| טעות | תיקון |
|---|---|
| צובעים ירוק כי הקוד קיים | ירוק דורש מבחנים שרצו בפועל, לא רק קובץ |
| מסכמים את `docs/` בלי לפתוח את `src/` | התיעוד מתאר כוונה; הקוד מתאר מציאות. פער ביניהם הוא בעצמו ממצא לדוח |
| שלב־אב ירוק עם תת-משימה צהובה | כלל הגלישה: אחד צהוב — כולם צהוב |
| מוסרים נתיב לקובץ בלי לבדוק שנוצר | לוודא שהפקודה דיווחה על בייטים שנכתבו |
| מתקנים תוך כדי את מה שהדוח חשף | הסקיל מדווח בלבד. התיקון הוא הצעה בסוף |
| נתיב יחסי בפקודת ההמרה | Chrome מפרש אותו ככתובת אינטרנט ונכשל. תמיד `$(pwd -W)` ונתיב מלא |
