# האוצֵר — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The assistant decides on her own, at the end of a job, what was worth remembering — and the past reaches every plan without the planner having to ask for it.

**Architecture:** A curator runs orchestrator-side at the `verify → remember` hop, builds a brief in code from the job record, asks a model for structured candidate facts, validates them against a positively-derived set of subjects the job actually touched, and writes them with provenance read from the job row. Retrieval is assembled in code and rendered last in the planner prompt, with every non-`boss` line labelled as somebody's claim.

**Tech Stack:** TypeScript (NodeNext ESM, `.js` on every relative import), Postgres 17 via `pg`, zod, vitest against a real database, `@anthropic-ai/claude-agent-sdk`.

**Spec:** `docs/superpowers/specs/2026-09-15-curator-design.md` — binding. Where this plan and the spec disagree, the spec wins.

## Global Constraints

- `.js` extension on every relative import, including from `.ts` files.
- `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `verbatimModuleSyntax` are all on.
- Hebrew for anything a human reads; English for identifiers, comments and internal errors.
- Every control is written as a **positive list**. "Everything that is not X" has silently swept in unintended cases three times in this codebase.
- A negative test must prove the thing it covers actually ran — a test that passes with its subject deleted is not a test.
- Tests run against a real Postgres. `resetDatabase()` in `src/test/db.ts` TRUNCATEs a hand-maintained list; a new table must be added to it by hand.
- The curator writes memory directly and **never** through the gate. It must not add a tool name, a `TOOL_ACTION_CLASS` entry, or an agent allowlist entry.
- The model never chooses provenance. `WriteMemoryInput` has no such field and must not gain one.
- `MAX_CURATED = 8`; `CURATION_RUNS_PER_DAY` default `20`; memory `body` is capped at 4,000 characters by the DB.

/**
 * Which finished jobs are worth a billed model call.
 *
 * The owner's decision (spec §2 row 5) is "when the job read or
 * communicated". Both halves of that sentence are already defined elsewhere
 * and enforced elsewhere: `ingestsExternalContent` is the table the
 * first-contact exemption reads, and `OUTBOUND_TOOLS` is the table that
 * decides redaction, quiet hours and the kill switch's outbound scope.
 *
 * This derives from both rather than restating either. A second list of
 * "tools that read" would be a second definition, and this codebase has
 * three separate incidents of exactly that drifting apart.
 */
import type { Plan } from '../domain/plan.js';
import { ingestsExternalContent, isOutbound } from '../policy/classify.js';

export function jobQualifiesForCuration(plan: Plan): boolean {
  return plan.steps.some(
    (step) => ingestsExternalContent(step.toolName) || isOutbound(step.toolName),
  );
}

```ts
/**
 * What the curator is shown, assembled in code.
 *
 * The brief carries external content — a supplier's document summary, the
 * body of a message that went out — so the curator is a quarantine reader in
 * the same sense `know.reader` is: its input is hostile by definition and it
 * holds no classified tool.
 *
 * `touched` is the important half. It is the set of subjects this job
 * actually addressed, derived from the plan's own steps, and Task 3's
 * validation refuses any candidate whose subject falls outside it. Built
 * here rather than in the validator because only this module reads the plan.
 */
import type { Queryable } from '../db/pool.js';
import { config } from '../config.js';
import { loadJob } from '../orchestrator/jobs.js';
import { loadPlanBody } from '../orchestrator/plan-store.js';
import { readEmails } from '../policy/facts.js';

export interface TouchedSubjects {
  /** Addresses the plan's outgoing steps were aimed at. */
  recipients: string[];
  /** Entity ids the plan's payloads named. */
  entityIds: string[];
}

export interface CurationBrief {
  text: string;
  touched: TouchedSubjects;
}

/**
 * Whole sections are dropped rather than cut mid-sentence, the same choice
 * `renderReadingBrief` makes: half a section is neither in nor out, and a
 * model asked to summarise half a sentence invents the other half.
 */
export const MAX_BRIEF_CHARS = 12_000;

export async function buildCurationBrief(
  jobId: string,
  options: { businessId?: string; db?: Queryable } = {},
): Promise<CurationBrief | null> {
  const businessId = options.businessId ?? config.businessId;

  const job = await loadJob(jobId, { businessId });
  if (job === null) return null;

  const stored = await loadPlanBody(jobId, { businessId });
  if (stored === null) return null;

  const recipients = new Set<string>();
  const entityIds = new Set<string>();
  const sections: string[] = [`# המשימה\n${job.title}`];

  for (const step of stored.plan.steps) {
    for (const address of readEmails(step.input)) recipients.add(address);
    const entityId = step.input['entityId'];
    if (typeof entityId === 'string' && entityId.trim() !== '') entityIds.add(entityId);

    const body = step.input['body'];
    if (typeof body === 'string' && body.trim() !== '') {
      sections.push(`# מה נשלח (${step.toolName})\n${body}`);
    }
  }

  let text = sections.join('\n\n');
  if (text.length > MAX_BRIEF_CHARS) {
    const kept: string[] = [];
    let used = 0;
    for (const section of sections) {
      if (used + section.length > MAX_BRIEF_CHARS - 20) break;
      kept.push(section);
      used += section.length + 2;
    }
    text = `${kept.join('\n\n')}\n\n[קוצץ]`;
  }

  return {
    text,
    touched: { recipients: [...recipients], entityIds: [...entityIds] },
  };
}
```

```ts
/**
 * The shape the curator may return, and the three checks that make writing
 * it safe without the gate.
 *
 * There is deliberately NO `provenance` field. Not merely unused — absent, so
 * a model that wanted to declare its own trust level has nowhere to write it.
 * The same structural choice `ProposeForReadingInput` and
 * `RunInstructionOptions` already make.
 */
import { z } from 'zod';
import { SafeLookupKey } from '../domain/charter.js';
import type { TouchedSubjects } from './curation-brief.js';

/** One job cannot teach the business more than this in one pass. */
export const MAX_CURATED = 8;

/** The column ceiling `024_memories.sql` already enforces. Checked before the write. */
const MAX_BODY_CHARS = 4_000;

export const CurationCandidate = z
  .object({
    kind: z.enum(['entity', 'preference', 'chunk']),
    // `SafeLookupKey` is a ZodEffects (it is `z.string().refine(...)`), so
    // `.min`/`.max` do NOT chain off it. Length first, then pipe through the
    // prototype guard. Preflight caught this.
    subjectKey: z.string().min(1).max(200).pipe(SafeLookupKey),
    attribute: z.string().min(1).max(200).optional(),
    body: z.record(z.string(), z.unknown()),
    sourceRef: z.string().min(1).max(500),
  })
  .refine((c) => (c.kind === 'preference') === (c.attribute !== undefined), {
    message: 'attribute is required for a preference and forbidden otherwise',
  })
  .refine((c) => JSON.stringify(c.body).length <= MAX_BODY_CHARS, {
    message: 'body exceeds the column ceiling',
  });
export type CurationCandidate = z.infer<typeof CurationCandidate>;

export const CurationResult = z.object({
  candidates: z.array(CurationCandidate).max(MAX_CURATED),
});
export type CurationResult = z.infer<typeof CurationResult>;

export interface Sifted {
  accepted: CurationCandidate[];
  rejected: Array<{ candidate: unknown; problem: string }>;
}

/**
 * The control that replaces the gate.
 *
 * A candidate may only be about somebody this job actually addressed or
 * named. A hostile document can make the assistant remember a claim about
 * ITS OWN sender — that is the influence decision 6 deliberately allows,
 * labelled — but it cannot make her remember anything about a third party the
 * job never went near. Without this, "remember that Dana approved a 40%
 * discount" is writable from any PDF.
 *
 * Positive membership, never "not in a deny list".
 */
export function siftCandidates(result: CurationResult, touched: TouchedSubjects): Sifted {
  const allowed = new Set<string>([...touched.recipients, ...touched.entityIds]);
  const accepted: CurationCandidate[] = [];
  const rejected: Array<{ candidate: unknown; problem: string }> = [];

  for (const candidate of result.candidates) {
    if (!allowed.has(candidate.subjectKey)) {
      rejected.push({ candidate, problem: 'subject_not_touched' });
      continue;
    }
    accepted.push(candidate);
  }

  return { accepted, rejected };
}
```

/**
 * The curator's one call to the model.
 *
 * It holds NO tools. The curator reads what a finished job did and returns
 * structured facts; a curator that could act would be a second, ungated path
 * to every capability — the same reason the planner carries `tools: []`.
 *
 * Bumping `CURATION_PROMPT_VERSION` is a manual, deliberate act, not a hash.
 * A changing hash would invalidate every stored judgement while the question
 * stayed the same — the reasoning `document_readings.prompt_version` already
 * carries.
 */
import { query, type Options } from '@anthropic-ai/claude-agent-sdk';
import { config } from '../config.js';
import type { CurationBrief } from '../memory/curation-brief.js';
import { CurationResult } from '../memory/curation-parse.js';

export const CURATION_PROMPT_VERSION = 'v1';

export type Curator = (brief: CurationBrief) => Promise<CurationResult>;

function refuseUnderTest(): void {
  if (!config.isTest) return;
  throw new Error(
    'curateWithModel: refusing to run under NODE_ENV=test — this is a live, billed call to the Agent SDK. ' +

/**
 * What the assistant decides to remember, on her own, when a job ends.
 *
 * This writes memory DIRECTLY and never through the gate, and the spec
 * argues why at length (§3): stage 8 holds the memory class at `draft_only`
 * for `unknown_external`, so curation through a tool would write nothing from
 * exactly the documents the owner decided must be remembered — labelled.
 * Three positive controls stand in for the gate: provenance read from the job
 * row (inside `writeMemory`), the subject required to be one the job actually
 * touched (`siftCandidates`), and the label travelling with the row into
 * every recall.
 *
 * Nothing here can fail a job. A job that did its work and cannot be closed
 * because a model did not answer is a bug, not a control.
 */
import type { Queryable } from '../db/pool.js';
import { getPool } from '../db/pool.js';
import { config } from '../config.js';
import { appendAudit } from '../audit/log.js';
import { canonicalHash } from '../util/canonical.js';
import { loadPlanBody } from '../orchestrator/plan-store.js';
import { curateWithModel, type Curator } from '../sdk/curator.js';
import { buildCurationBrief } from './curation-brief.js';
import { siftCandidates } from './curation-parse.js';
import { jobQualifiesForCuration } from './curation-trigger.js';
import { recallMemories, writeMemory } from './store.js';

export interface CurationOutcome {
  ran: boolean;
  skipped: 'not_qualified' | 'no_plan' | 'no_key' | 'over_cap' | null;
  written: number;
  rejected: number;
}

export interface CurateJobOptions {
  businessId?: string;
  /** Injected by tests. Production leaves it unset and gets the billed call. */
  curator?: Curator;
}

/**
 * The daily ceiling counts AUDIT rows, not `memories` rows.
 *
 * `memories` carries no column saying who wrote a row — `written_by_job`
 * names a job, not a curator — so counting there could not tell a row the
 * curator wrote from one a plan's `memory.write_*` step wrote, and a ceiling
 * meant to fence billed calls would have been closed by writes that cost
 * nothing. Counting audit rows also counts a call that returned no
 * candidates, which is precisely a call that was paid for.
 */
export async function curationRunsToday(
  options: { businessId?: string; db?: Queryable } = {},
): Promise<number> {
  const businessId = options.businessId ?? config.businessId;
  const db = options.db ?? getPool();
  const { rows } = await db.query<{ n: string }>(
    `SELECT count(*)::text AS n FROM audit_log
      WHERE business_id = $1 AND kind = 'curation' AND at >= date_trunc('day', now())`,
    [businessId],
  );
  return Number(rows[0]?.n ?? '0');
}

export async function curateJob(
  jobId: string,
  options: CurateJobOptions = {},
): Promise<CurationOutcome> {
  const businessId = options.businessId ?? config.businessId;
  const idle: CurationOutcome = { ran: false, skipped: null, written: 0, rejected: 0 };

  const stored = await loadPlanBody(jobId, { businessId });
  if (stored === null) return { ...idle, skipped: 'no_plan' };
  if (!jobQualifiesForCuration(stored.plan)) return { ...idle, skipped: 'not_qualified' };

  // Same switch discipline as DOCUMENT_INBOX: no key means the feature is off,
  // reported rather than silently identical to "nothing to remember".
  if (options.curator === undefined && (process.env['ANTHROPIC_API_KEY'] ?? '') === '') {
    return { ...idle, skipped: 'no_key' };
  }
  if ((await curationRunsToday({ businessId })) >= config.curationRunsPerDay) {
    return { ...idle, skipped: 'over_cap' };
  }

  const brief = await buildCurationBrief(jobId, { businessId });
  if (brief === null) return { ...idle, skipped: 'no_plan' };

  const curator = options.curator ?? curateWithModel;

  let written = 0;
  let rejected = 0;
  try {
    const result = await curator(brief);
    const sifted = siftCandidates(result, brief.touched);
    rejected = sifted.rejected.length;

    for (const candidate of sifted.accepted) {
      const resolved = await resolveConflict(candidate, jobId, businessId);
      await writeMemory(
        {
          jobId,
          kind: resolved.kind,
          subjectKey: candidate.subjectKey,
          ...(resolved.kind === 'preference' ? { attribute: candidate.attribute ?? null } : {}),
          body: resolved.body,
          sourceRef: candidate.sourceRef,
        },
        { businessId },
      );
      written += 1;
    }
  } catch {
    // The job is finished either way. A curator that throws must not strand it.
    return { ...idle, written, rejected };
  }

  await appendAudit(
    {
      actor: 'orchestrator',
      kind: 'curation',
      charterVersion: 'n/a',
      provenance: 'boss',
      // Counts only. A subject here would put the contact's identity into the
      // one table an erasure deliberately cannot reach.
      inputHash: canonicalHash({ jobId, written, rejected }),
      artifacts: [],
      costMinor: null,
      tokens: null,
      reason: `אצירה · ${written} עובדות נשמרו · ${rejected} נדחו`,
    },
    { businessId },
  );

  return { ran: true, skipped: null, written, rejected };
}

/**
 * Decision 3, expressed in the schema's terms.
 *
 * `memories` carries partial unique indexes: one live entity per subject, one
 * live preference per `(subject, attribute)`. "Both alive side by side" is
 * therefore not a state the schema permits, so an external claim that
 * contradicts something the OWNER said is written as a `chunk` instead —
 * which carries no uniqueness. The owner's row stays the live fact and the
 * supplier's claim is recorded as what it is.
 */
async function resolveConflict(
  candidate: { kind: 'entity' | 'preference' | 'chunk'; subjectKey: string; attribute?: string; body: Record<string, unknown> },
  jobId: string,
  businessId: string,
): Promise<{ kind: 'entity' | 'preference' | 'chunk'; body: Record<string, unknown> }> {
  if (candidate.kind === 'chunk') return { kind: 'chunk', body: candidate.body };

  const { rows } = await getPool().query<{ provenance: string }>(
    'SELECT provenance FROM jobs WHERE job_id = $1 AND business_id = $2',
    [jobId, businessId],
  );
  const incoming = rows[0]?.provenance;

  const live = await recallMemories(
    { subjectKey: candidate.subjectKey, kind: candidate.kind },
    { businessId },
  );
  const existing = live.find(
    (m) => m.kind !== 'preference' || m.attribute === (candidate.attribute ?? null),
  );

  if (existing?.provenance === 'boss' && incoming !== 'boss') {
    return {
      kind: 'chunk',
      body: {
        claim: candidate.body,
        about: candidate.attribute ?? candidate.subjectKey,
        note: 'טענה חיצונית שסותרת את מה שהבעלים אמר — נשמרה כטענה ולא כעובדה',
      },
    };
  }

  return { kind: candidate.kind, body: candidate.body };
}

```ts
/**
 * The past, assembled in code and handed to the planner.
 *
 * Not a tool the model calls and not a search it steers: `docs/06-memory.md`
 * rejects a general `search_everything` by name as unbounded in cost and
 * impossible to audit. The caller names the subjects; this returns text.
 *
 * Two rules carry the safety. Scope is positive — only the subjects this job
 * touches, so a stranger's claim cannot surface in a plan that has nothing to
 * do with them. And every row whose provenance is not `boss` is rendered as an
 * attributed claim, in the renderer and not as an instruction in the prompt,
 * because that is the difference between influence and an injection that
 * worked.
 */
import { config } from '../config.js';
import { recallMemories, type MemoryRecord } from './store.js';

export const MEMORY_BLOCK_BUDGET_CHARS = 3_000;

function renderRow(memory: MemoryRecord): string {
  const value = JSON.stringify(memory.body);
  if (memory.provenance === 'boss') {
    return `- ${memory.subjectKey}${memory.attribute ? ` · ${memory.attribute}` : ''}: ${value}`;
  }
  const source = memory.sourceRef === null ? '' : ` (${memory.sourceRef})`;
  return `- ${memory.subjectKey}: נטען${source} — ${value}`;
}

export async function recallForPlanning(
  subjects: string[],
  options: { businessId?: string; budget?: number } = {},
): Promise<string> {
  const businessId = options.businessId ?? config.businessId;
  const budget = options.budget ?? MEMORY_BLOCK_BUDGET_CHARS;

  const found: MemoryRecord[] = [];
  for (const subject of subjects) {
    found.push(...(await recallMemories({ subjectKey: subject }, { businessId })));
  }
  if (found.length === 0) return '';

  // Least important out first: external claims go before the owner's facts.
  const ordered = [...found].sort((a, b) => {
    const rank = (m: MemoryRecord): number => (m.provenance === 'boss' ? 0 : 1);
    return rank(a) - rank(b);
  });

  const header = '# מה ידוע מהעבר';
  const lines: string[] = [];
  let used = header.length;
  for (const memory of ordered) {
    const line = renderRow(memory);
    if (used + line.length + 1 > budget) continue;
    lines.push(line);
    used += line.length + 1;
  }
  if (lines.length === 0) return '';

  return `${header}\n${lines.join('\n')}`;
}
```
