# עוזרת אישית עסקית — סקירת ארכיטקטורה

**גרסה 0.1 · מסמך ארכיטקטורה · TypeScript + Claude Agent SDK · התקנה נפרדת לכל עסק**

---

## החזון

מוצר שמחליף **מזכירה או פקידת משרד** בעסק. לא קשור לעסק ספציפי — מותקן אצל מגוון עסקים ולומד כל אחד מהם.

המערכת אינה chatbot. היא יודעת **להבין → לחשוב → לתכנן → לבצע → לבדוק → לעקוב → לזכור → לעדכן**, ומבצעת פעולות עצמאיות בעולם האמיתי: שולחת מיילים, קובעת פגישות, מזמינה מוצרים, מתכתבת עם לקוחות, ומתחברת ל-CRM ולהנהלת חשבונות.

מכיוון שהיא פועלת עצמאית, יש לה **תקנון עסקי** — מסמך חתום שמגדיר את אופי העסק, המדיניות שלו והגבולות שלו — ומנגנון שמזהה פעולות רגישות או חריגות ומנתב אותן לאישור אנושי.

## שתים-עשרה היכולות

קריאה, לימוד וסיכום של מאמרים ומכתבים · מענה למיילים · קביעה ותיאום פגישות והכנסתן ליומן · כניסה לדפדפן, הזמנת מוצרים וביצוע פעולות באתרים · התכתבות בוואטסאפ עם אנשי הקשר של הבוס · זיכרון עסקי · תזכורות אירועים · סיכום יומי ושבועי · חיבור ל-CRM ולהנהלת חשבונות · פולואפ על משימות עד לביצוען · בנייה מתקדמת באקסל וכתיבה בוורד · עיצוב תמונות וסרטונים.

## חמש ההחלטות שמעצבות את כל השאר

אלה חמש הכרעות היסוד. אם חולקים על אחת מהן, רוב יתר הארכיטקטורה משתנה.

| # | החלטה | נימוק |
|---|---|---|
| 1 | **ה-Orchestrator הוא שירות TypeScript דטרמיניסטי עם מכונת מצבים עמידה — לא סשן Claude שמנהל סוכנים.** Claude נקרא *בנקודות החלטה*, לא כלולאת הבקרה. | עבודה נמשכת ימים, חייבת לשרוד קריסות ולהיות ניתנת לביקורת. שיחת LLM אינה אף אחד משלושת אלה. |
| 2 | **תוכן לא-אמין וסמכות לבצע או להוציא כסף לעולם לא חיים באותו חלון הקשר.** קוראים לא מקבלים כלי פעולה; מבצעים מקבלים אובייקטים מובנים ולעולם לא טקסט חיצוני גולמי. | ההגנה המבנית היחידה מול prompt injection. כל השאר הוא עומק. |
| 3 | **התקנון מקומפל לפרדיקטים שנאכפים ב-`PreToolUse` hooks — לא פרוזה שמבקשים מהמודל לציית לה.** המודל מקבל פרוזה לשיפוט; ה-hook מקבל JSON לאכיפה. במחלוקת, ה-hook מנצח. | "הסוכן קרא את המדיניות" זו לא בקרה. hook כן. |
| 4 | **אישור אנושי לעולם לא חוסם סוכן רץ.** ה-hook דוחה עם `queued_for_approval`, הריצה נגמרת, המצב נשמר, וריצה *חדשה* מתחדשת עם האישור. | אישור יכול לקחת שש שעות. להחזיק `query()` פתוח שש שעות זו קטסטרופה תפעולית. |
| 5 | **אוטונומיה נרכשת לכל מחלקת פעולה לפי הסכמה נמדדת, לא מוגדרת באופטימיות.** כל מחלקה מתחילה ב-`draft_only` ומקודמת רק אחרי N דגימות ב-≥95% אישור-ללא-עריכה. | התשובה הכנה לשאלה "מה קורה כשהיא טועה והעסק נפגע". |

## מה ה-SDK נותן מול מה שצריך לבנות

| יכולת | מקור |
|---|---|
| לולאת סוכן, קריאת כלים, retry על שגיאות חולפות | **SDK** |
| דחיסת הקשר ו-`PreCompact` hook | **SDK** — חובה להשתמש ב-hook כדי לשטוף מצב job |
| התמדת סשן ו-`resume` | **SDK** |
| תת-סוכנים עם הקשר מבודד, מודל וכלים משלהם | **SDK** — לפיזור בתוך צעד בלבד |
| לקוח MCP: stdio / HTTP / SSE | **SDK** — כך Zapier והאינטגרציות המרוחקות מתחברות |
| **שרתי MCP בתוך התהליך** (`createSdkMcpServer` + `tool()`) | **SDK** — הפרימיטיב הכי שימושי כאן: זיכרון, תקנון, אישורים ומשימות הופכים לכלים מוטפסים בלי IPC |
| `PreToolUse` / `PostToolUse` / `SessionStart` / `Stop` / `PreCompact` hooks | **SDK** — תפר האכיפה. הלוגיקה בתוכם היא שלנו |
| `allowedTools` / `disallowedTools` / מצבי הרשאה | **SDK** — יכולת גסה לכל סוכן |
| Skills (חשיפה הדרגתית) | **SDK** — כך `prod.docs` מקבל מיומנות xlsx/docx בלי נפיחות פרומפט |
| חשבונאות עלות וטוקנים לכל ריצה | **SDK** |
| `interrupt()` על שאילתה רצה | **SDK** — רכיב אחד ב-kill switch |
| **Orchestrator עמיד, מכונת מצבים, תור, scheduler, wakeups** | **בנייה** — ליבת המוצר |
| **סכמת התקנון, קומפיילר, מפרש פרדיקטים, חתימה** | **בנייה** |
| **ניקוד סיכון + מנוע נורמות וחריגות** | **בנייה** |
| **ApprovalBroker, מסירה רב-ערוצית, קשירת TOCTOU, timeouts** | **בנייה** |
| **שירות הזיכרון: כל השכבות, אריזת אחזור, ממשל כתיבה** | **בנייה** |
| **audit משורשר-hash + שחזור + הסברים בשפה פשוטה** | **בנייה** |
| **פרוטוקול ה-envelope, מרשם intents, שומרי לולאה** | **בנייה** |
| **kill switch ששורד restart וחוסם את התור** | **בנייה** — `interrupt()` מכסה רק את הריצה הפעילה |
| **מתאמי ערוצים + קליטת webhooks + דה-דופליקציה + חותמת מקור** | **בנייה** |
| **CredentialBroker / תיווך יכולות** | **בנייה** |
| **הקשחת סנדבוקס הדפדפן + recipes לכל אתר** | **בנייה** |
| **מושל עלויות ומעטפות תקציב** | **בנייה** |
| **רמפת אוטונומיה + מערך evals + shadow mode** | **בנייה** |
| **דשבורד** | **בנייה** |

**החלוקה בגסות: ה-SDK מסיר כ-30% מהעבודה** — בדיוק את החלק שהוא זמן הריצה של הסוכנים. **70% הנותרים — ממשל, עמידות, זיכרון ואינטגרציה — הם המקום שבו המוצר באמת חי.** מי שחושב "Agent SDK + פרומפטים = מזכירה" מעריך בחסר פי שלושה בערך.

> **סימון אי-ודאות:** שמות וחתימות מדויקים ב-SDK (`createSdkMcpServer`, מבנה ה-payload של hooks, והאם `canUseTool` דורש מצב streaming בגרסה הנוכחית) צריכים אימות מול התיעוד לפני המימוש. הארכיטקטורה אינה תלויה בפרטים האלה; קוד החיווט כן, וה-SDK זז.
